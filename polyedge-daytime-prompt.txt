In `config/settings.yaml`, `kelly_fraction: 0.5` (half-Kelly). Research shows:
- At 0.5x Kelly with a 45-55% win rate, drawdowns can reach 50-80% of capital
- Professional prediction market traders use 0.15-0.25x Kelly maximum
- One Kalshi bot study found 0.75x Kelly "compounds losses catastrophically"

**Fix**: Change to 0.25 in settings.yaml AND in `src/risk/kelly_sizer.py`:
- Default kelly_fraction: 0.25 (quarter-Kelly)
- Add dynamic Kelly: scale between 0.15 (losing streak) and 0.30 (winning streak)
- Track rolling 20-trade win rate; adjust Kelly proportionally
- Run parameter sweep to confirm: `python3 -m scripts.backtest_engine --sweep kelly_fraction=0.10,0.15,0.20,0.25,0.30,0.50`

### 2B: Daily Loss Limit — Currently 15% (Too Generous)
In settings.yaml `daily_loss_limit_pct: 0.15`. That means the bot can lose $750 of a $5000 bankroll in a single day before stopping.

**Fix**: Reduce to 0.08 (8%). Add escalating cool-down:
- After 5% daily loss: reduce position sizes by 50% for rest of day
- After 8% daily loss: halt all trading until next day
- After 20% total drawdown from peak: halt until manual review

## SECTION 3: PREDICTION ACCURACY IMPROVEMENTS

### 3A: Ensemble Extremization — NOT IMPLEMENTED
Research shows extremizing ensemble forecasts by 15-25% improves accuracy. The current `ensemble.py` does weighted averaging but NO extremization.

**Fix**: Add extremization to `ensemble_forecast()` and `multi_model_ensemble()`:
```python
def extremize(probability: float, factor: float = 1.2) -> float:
    """Push probability away from 50% toward 0 or 1.
    
    Research: extremizing aggregated forecasts improves calibration
    because averaging pulls too far toward 50%. Factor of 1.2 = 20% extremization.
    """
    if probability <= 0.01 or probability >= 0.99:
        return probability
    # Log-odds extremization
    import math
    log_odds = math.log(probability / (1 - probability))
    extremized_odds = log_odds * factor
    result = 1 / (1 + math.exp(-extremized_odds))
    return max(0.01, min(0.99, result))
```
Apply AFTER the weighted average, BEFORE edge calculation. Make the factor configurable in settings.yaml. Default 1.15 (conservative).

### 3B: Platt Scaling Post-Hoc Calibration — NOT IMPLEMENTED
Research shows Platt scaling brings AI forecasters to near-superforecaster accuracy. The current `calibration.py` tracks Brier scores but doesn't apply post-hoc calibration to future predictions.

**Fix**: Add `src/analysis/platt_calibrator.py`:
1. Collect historical (predicted_probability, actual_outcome) pairs from calibration_records
2. Fit a logistic regression: `calibrated = 1 / (1 + exp(-(a * raw_prob + b)))`
3. Apply to all new forecasts BEFORE they enter the ensemble
4. Re-fit weekly as more data accumulates
5. Require minimum 50 resolved predictions before activating
6. Track Brier score with and without Platt scaling to measure improvement

### 3C: Category Auto-Gating — PARTIALLY IMPLEMENTED
`ai_probability.py` loads `_category_brier_scores` from calibration but doesn't hard-block categories with bad Brier scores.

**Fix**: Add to `scan_for_opportunities()`:
